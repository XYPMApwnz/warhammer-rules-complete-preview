Minimal PWA — current V2 boundary

Unified V2 is the sole supported user interface. Legacy V1 readers, old URL
compatibility, Roster Guides, V1 roster storage and historical V1 transitions
are retired by the owner. They must not return as acceptance requirements.

The existing worker prepares the V2 entry/code/shared styles. Large Army Book
JSON and both glossary payloads remain lazy. Both datasheet-system.css and
unit-art.css are mandatory. The Core reader still needs its lazy
glossary/v2/generated/index.en.js definition data.

Updates require the existing explicit confirmation button. Other tabs are not
automatically reloaded. Current V2 localStorage rosters and unfinished import
drafts are retained. Version checks before/after view preparation refuse
incompatible results before mount; no per-tab version/cache framework exists.

Mutable V2 resources use network-first with SHA-compatible offline fallback.
Compatible cached native JSON and the exact Core definition JS are copied and
verified against the current runtime manifest before obsolete own caches are
removed. Copy/read/hash failure keeps old caches for a later startup retry.
No opening books or validating UI runs within the worker.

The root redirects to the existing v2/app.html; its manifest metadata owns PWA
installability. The existing webmanifest start URL remains the root.
Previously opened compatible books work offline while storage is retained.
Changed bytes, eviction and quota can limit offline access. Unit art migration
and an offline library manager are not implemented. Safari/iOS are untested.
Future top-level side effects in dynamically imported modules remain a risk;
current book factories must preserve pure preparation and the real-factory
transition regression gate.

tests/cache-revision-portability-qa.mjs,
tests/minimal-pwa-import-purity-qa.mjs, v2/pwa-transition-qa.mjs,
