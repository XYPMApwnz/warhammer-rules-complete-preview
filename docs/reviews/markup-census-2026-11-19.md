## Counting and classification contract

One row identifies one physical named source rule, or an exact named source member/field. `rule_id` is the existing canonical ID; where an aggregate section contains several rules, an audit locator adds the exact source field/component. These locators are report addresses, not new production identities. No source rule was invented or rewritten.

- ARMY_RULE counts named component definitions instead of a textless aggregate root. DETACHMENT_RULE includes its own non-child procedure and explicit separately named components/table bonuses; parent and child clause IDs are separated. Table headers, battle-size caps and lookup-only ranges are not extra rules.
- ENHANCEMENT and STRATAGEM count native owners. ABILITIES containers split into exact named `blocks/N/text`; semantic individual entities are retained directly. Named special sections, damaged rules and source supplements with an effect are included. Pure composition/Leader/Support/Transport selection containers are excluded; an actual Core Leader membership is still counted.
- CORE_ABILITY is one native membership occurrence per datasheet, not per model copy. A nonempty exact native ability binding is EXECUTED as presence/parameters; reference-only membership with owner-bound full Core text is RECIPIENTS_ONLY. This does not automate the ability's battlefield action.
- WARGEAR_ABILITY includes non-weapon equipment effects, drone definitions and the custom Harpooned weapon effect. An equipment option and its linked effect are not counted twice as two independent rules. Ordinary intrinsic weapon stat/trait tokens and selection-only wargear permissions are accepted base facts, outside this rule-effect denominator.
- **EXECUTED:** actual supported operation, physical ability-presence binding, selected provided-weapon lowering or enforced native permission exists. Conditions are not presumed TRUE. Composite rules can retain independent battle-only text; `partial_coverage` discloses this.
- **RECIPIENTS_ONLY:** an actual consumed canonical ATTACHED/F1/policy path, physical Core membership or friendly Stratagem compatibility-target channel supplies qualified source text. Stratagem applicability does not claim every consequence propagates or CP is spent automatically. An OWNER/ACTOR/ANCHOR role alone is insufficient.
- **TEXT_ONLY_INTENDED:** a specific independent source review, deliberate native conditional-only presentation policy, or explicit non-roster-output decision explains why the player resolves the action at the table. Generic BATTLE_ONLY/DISPLAY_ONLY is insufficient by itself.
- **GAP:** a current exact source clause retains independently reviewed, unresolved recipient/condition debt. It can be battle-dependent annotation debt without a visible broken roster value. Partially implemented rules remain partial, rather than being reported as completely absent.
- **UNKNOWN:** no defensible automatic resolution of coverage/intent, or an accepted unresolved source conflict. Actor-only permissions are not fabricated effect recipients. Generic SM text retention explicitly says it does not decide whether automation is out of scope.

This is a native-data and consumer-path census, not a new exhaustive browser reproduction. Existing same-SHA runtime captures are reused only where named. A field/rule being displayed on its source card does not prove it propagates to another physical unit.

Cross-book normalization promotes 42 source-exact Core Leader/Support membership rows from reference-only to EXECUTED where a real native attachment policy enforces that permission. This is the same criterion used for SM/BA/DA; it does not equate empty ability arrays with an applied grant. `category-normalization.csv` records each exact before/after audit decision and its policy source IDs. No production data changed.

## One metric and one future gate (proposal only)

Proposed command: `npm run markup:census -- --check` (and explicit `--report=<path>` for review). It should read passports and the same native factories/final books, normalize stable physical rule occurrences once, and print N plus the five counts by book/kind, minimum resolved-category fraction, partial coverage count, new/resolved gaps, undecided identities and runtime. Do not reuse stale hardcoded product baselines or decide intent from prose/name heuristics.

The single headline metric is **minimum resolved-category coverage** `(EXECUTED + RECIPIENTS_ONLY + TEXT_ONLY_INTENDED) / N`, accompanied obligatorily by GAP, UNKNOWN and partial counts. Automation percentage is diagnostic, never a target of 100%. A reviewed category ledger must be versioned by canonical owner + exact source field/clause fingerprint; one effect must not certify an unrelated source paragraph.

Proposed strict gates:

1. New or changed rule/source member without an explicit reviewed category and evidence → FAIL, with book/ID/source field. No generated default TEXT_ONLY exemption.
2. Source fingerprint changes invalidate its old disposition until reviewed. Removed source rule must have explicit retirement; inherited identity cannot disappear silently.
3. EXECUTED requires supported operation/real native binding, provable condition inputs and a matching source/recipient path; a roster-level condition lacking its computer cannot masquerade as executed. RECIPIENTS_ONLY requires an actual consumed ATTACHED/F1/related-target path and complete source text, not an actor/anchor or orphan recipient.
4. TEXT_ONLY_INTENDED requires a reason/authority record. UNKNOWN/GAP cannot grow against a reviewed exact-ID baseline; existing debt is an exact named allow-list with owner/next action, never a count-only allowance. Resolving debt requires reviewed evidence, not recategorization to meet a percentage.
5. A partial rule must list the coverage of all its source fragments; mandatory direct roster-stat/weapon clauses must execute when their necessary inputs are known. Retain physical owner, MODEL/UNIT/formed scope and all battle qualifications.
6. Deterministic output, duplicate-ID and denominator completeness checks; explicit negative controls for missing category, stale fingerprint, orphan recipient, removed computer and source-field loss. These controls are **proposed, not implemented/run** in this task.

Runtime budget: read-only extraction of nine already-built native books and declared reviews should target **≤10 seconds**, with a hard diagnostic ceiling around 30 seconds on this PC. Sequential external read-only extraction measured **2.30s** total (SM family 0.81s; AM/DG/Tau 0.60s; EC/Tyr/CSM 0.90s); a second extraction produced byte-identical rule inventories for all three groups. The separate nine-book executable-text audit measured **2.48s** including decoding publications and reading existing 507-state evidence. Report assembly/input hashing adds approximately one second. These are local read-only audit samples, not a benchmark promise or test-suite execution. No browser/build/clone/pre-ff is required for this metadata gate. Browser/source-backed physical-scope witnesses remain separate acceptance evidence; a fast census cannot replace them.
