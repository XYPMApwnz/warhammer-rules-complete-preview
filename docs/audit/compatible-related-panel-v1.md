# Shared book compatibility panel

Baseline: `427796be5d29766acedc59338537f04667c0ba67`.

## Ownership and scope

`books/shared/rule-contract-v2/book-related.mjs` is the shared Cartesian
relatedRules builder. The existing AM, DG and CSM factual/compiler adapters
remain inputs; their output property order, role details and publication bytes
are preserved. The six former placeholder producers use explicit intrinsic
MODEL/profile bindings and the same typed compatibility kernel.

The unbound book view does not claim a physical assignment or battle event.
An intrinsically incompatible candidate is NO_MATCH; a potentially eligible
candidate remains CONDITIONAL. MODEL Enhancements require the existing general
CHARACTER-bearer rule; source-declared UNIT upgrades retain their UNIT selectors.
Another attached component cannot supply an Enhancement bearer's keywords.

The owner clarification requires real Stratagem TARGET roles and
compatibilityRoleIds in book contracts, including inherited SM contracts in
DA/BA. An ephemeral book-only source of targets is explicitly rejected. Roster
related changes are intentional; imports, applied effects, characteristics,
weapons and prices remain protected independently.

## Source exception: Faultless Opportunist

`detachment-peerless-bladesmen:enhancement:1` intentionally has an unrestricted
MODEL owner. The current official v1.3 replacement says:

> You can target this unit with the Heroic Intervention stratagem, regardless of any other uses of that stratagem this phase.

It removes the historical Waha prefix `EMPEROR’S CHILDREN model only.` The
accepted instruction is `ec-official-v1.3:accepted-occurrence-05`; the existing
producer explicitly documents this replacement in
`books/emperors-children/v2/rule-contract-permission-declarations.mjs`.
No superseded qualifier or invented current selector is restored. The common
book CHARACTER-bearer rule still excludes non-CHARACTER units from its panel.

## Compiler input boundary

The six new consumers submit eligibility contracts and explicit keyword
projections to the compatibility compiler. Unrelated physical execution
contracts remain in the actual book/runtime, not in this disposable query
domain. This prevents a source-bound boolean inside a DA physical effect from
being misclassified as a manual pairwise answer by the existing guard. The
guard, canonical entities, runtime contracts and validators are not weakened.
