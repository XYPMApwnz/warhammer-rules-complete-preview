# Source references

Runtime proofs can name a binding slot such as `sourceEquipmentProvenance` without recreating that legacy object field. `copySourceEvidence` writes the slot into the common binding tuple; consumers read it with `sourceSnapshot(record, {slot})`. Test mutations republish named slots through the same source format, retaining their strict source comparison.

`books/shared/source-refs-v2/source-refs.mjs` supplies one source-reference format for all nine V2 books. This format records provenance already accepted by the book producers; it does not create source facts, infer recipients, or translate rule text. Stratagem declarations remain in their existing format.

Published records have `sourceRefs: [{documentId, referenceId, locators, ...}]`. `documentId` addresses one document table per book in `books/shared/source-refs-v2/source-catalog.json`. A document row stores the registered `sourceId`, document path, paired document hash, authority and recorded currentness. Locators, fragment hashes and document/corpus role stay on the individual reference. `referenceId` authenticates that complete document/locator association; changing a locator cannot silently create accepted evidence. A document and its corpus remain separate references with their own hashes. An unregistered or ambiguous document is explicitly `UNRESOLVED_SOURCE`. Captured or canonical entity IDs retain their identity meaning in typed contexts; an unknown entity ID alone does not create an unresolved document reference.

`sourceOwnership` separates canonical rule/entity ownership from document identity. Canonical `card.fields[].source` pointers and quotation-only `evidence` are not document references and are unchanged. Currentness document declarations use the common bindings; display strings retain their existing text.

`sourceBindings` addresses a shared immutable binding tuple. The tuple connects each original slot to reference indices, value-free layouts and typed identity/attribute contexts. The same tuple, layout and context are stored once across published snapshots; source-only JSON fields are serialized compactly. Compiler scratch objects and unpublished artifacts may retain inline catalogs for metadata outside the published closure. The inverse reconstructs every original declaration and key order. No legacy provenance object is duplicated, and the shared catalog does not become a gameplay-fact owner.

Document-bearing objects also occur outside named provenance slots: captured model references, bare file evidence, suppression proofs and table occurrences. Their document, locator, paired hash and source metadata fields use `sourceBindings.recordReference`. Its `fields[]` lists the exact original source-only fields in their original order. Ordinary `quote`, `field`, `role`, recipient and `factTableIds` metadata stays inline; evidence arrays retain their structure. `sourceSnapshot(record, {book, slot: 'recordReference'})` returns the original source-field subset. `sourceDeclarationView` flattens that subset back into the original object in its original order. `readSourceRefs(record, {book})` includes the record reference by default.

Locators preserve literal values. Opaque `selector`, marker/template/weapon-row selectors and numeric `line` values use `TEXT_LOCATION`; `pages` uses `PDF_PAGE` with its original array value. Explicit `xpath` uses `XPATH`, and document pointers use their JSON/HTML pointer kind where established by the document format. Layouts preserve the original field names, including the difference between `page` and `pages`.

Only established hash pairings enter document references: `sha256` and fragment `textSha256` with the primary document, `corpusSha256` with `corpusDocument`, and `sourceSha256` with `sourceDocument`. Paired `sourcePaths[]`/`sha256s[]` retain their index associations. Other purpose-specific hashes stay typed attributes under their original names; their presence does not establish which document they describe. Canonical currentness contains only `sourceVersion`, `effectiveDate`, `observedAt` and `acceptedBaseHead`. An original `effectiveFrom` remains an attribute context with its exact name and value.

A legacy `sourceId` containing a `books/`, `core/`, `mfm/` or HTTP document path plus an explicit locator is a document-path alias. Its layout restores the original `sourceId` field, while the normalized reference resolves the document through the registry. In this form the original `sha256` stays an attribute context: enrolled presentation instructions use it for fragment text, so it cannot assert document bytes. A surrounding holder such as `source` or `suppressionProvenance` can be read with `sourceSnapshot(parent, {book, slot: holderName})`; the fallback decodes its nested normalized proof and validates its catalogs.

Producers call `compileBookSourceRefs` and the common serializer. `tools/audit/build-source-catalog.mjs` consolidates current producer outputs deterministically; `--check` is read-only. Its explicit `--from-base` bootstrap is restricted to the exact reviewed migration HEAD, and is not the normal rebuild path. Consumers use `readSourceRefs`, `getRecordedSourceIdentity`, `hasRecordedSourceEvidence`, `sameSourceEvidence` or `copySourceEvidence`. Shared entries are content-verified before first use and then frozen. Validated source metadata can be shared by `cloneSourceBook` while ordinary gameplay fields remain independent copies. Replaced metadata, legacy shadows and mutable inline catalogs are still checked; cached entries cannot be relabelled under a different content identity. `sourceSnapshot` returns a mutable inverse copy; internal identity/equality reads reuse an immutable decoded view.

`tools/audit/source-refs-translation-report.mjs --check` inventories normalized slots from a fresh baseline compilation with the repository source registry, compares them to every generated artifact, checks all original fields and their order through the inverse, verifies established document/hash associations, and checks byte-identical stratagem serialization. `--write` regenerates the deterministic report; optional browser/package measurements remain separate attestations. `v2/source-refs-browser-parity.mjs` separately compares exact rendered card text and Source/Applies to labels through native imports, physical roster operations, reload and normal Service Worker offline transport. Static equality alone does not establish browser parity.
